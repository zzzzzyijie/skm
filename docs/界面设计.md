# SKM UI MVP 方案

## 背景

`skm` 是一个用 Go 编写的 AI Agent Skill 管理 CLI 工具，核心功能包括：
- **Library 管理**：`add`、`list`、`show`、`remove`、`prune`
- **Activation 管理**：`enable`、`disable`、`plan`、`apply`、`status`、`doctor`
- **Source 管理**：`source add/list/update/remove`、`sync`
- **Tag 管理**：`tag list/add/remove/rename`
- **Project 管理**：Web UI 支持 `project add/list/show/link/copy/unlink/status/unregister` 的
  本机项目部署流程；CLI 仍支持完整的 `project skills/require/vendor/remove/apply`

现在要为这个 CLI 工具增加一个 Web UI 前端，MVP 版本。

## 架构方案选择

### 方案 A：Go 内嵌 HTTP Server + 前端单页面（采用）

在 Go 项目中增加一个 `internal/server` 包，提供 REST API，并用 `embed` 嵌入前端静态文件。用户通过 `skm ui` 命令启动本地 Web 服务。

```text
用户执行: skm ui
         → 启动 HTTP Server (localhost:9527)
         → 浏览器打开 Web UI
         → UI 通过 REST API 调用后端
         → 后端复用现有 store/catalog/planner 逻辑
```

**优势**：
- 零依赖部署，单个二进制文件包含一切
- 完全复用现有 Go 业务逻辑（`store`、`catalog`、`planner` 等）
- 无需额外安装 Node.js 或任何运行时
- 与 CLI 共享同一份数据，天然一致
- `go:embed` 可将前端资产嵌入二进制，分发简单

## 前端技术栈

| 层面 | 选型 | 理由 |
|------|------|------|
| 框架 | 原生 HTML/CSS/JS（单页应用） | MVP 无需框架，减少构建依赖 |
| 构建 | 无（直接 `go:embed`） | 最小化工具链 |
| 样式 | Vanilla CSS + CSS Variables | 可控、轻量 |
| 交互 | Fetch API + DOM 操作 | MVP 足够 |

## MVP 功能范围

### 核心页面（3 个）

#### 1. Library 管理
- 页面顶部展示 Skill 总数和 Git Source 数量
- Skill 列表（支持按 Tag 筛选）
- Skill 详情查看
- 添加 Skill：本地目录导入，或通过 Git URL、GitHub 简写、`npx skills add` 命令导入仓库来源
- 移除 Skill
- Skill 与 Prompt 共用标签管理（新增、重命名、删除未使用标签）
- 添加 Skill、导入 Git Source 和编辑 Skill 时从已有标签中多选
- Agent 管理扫描本机已知 Agent 目录，区分“已检测”和“其他支持”，由用户决定纳入管理的 Agent
- Claude Code、Codex 与其他 Agent 一样可添加或移除；支持添加带自定义 Skill 目录的 Agent
- 每个 Skill 直接切换当前已管理 Agent 的启用状态
- Git 来源的 Skill 详情中支持更新来源
- 本地导入通过 macOS Finder 选择 Skill 文件夹

Activation 不再作为独立导航页面，启用状态在对应的 Skill 卡片中完成。

#### 设置与 Git 同步

- 侧边栏提供设置入口，包含中英文切换、暗黑模式，以及 Git Source 配置。
- Git 设置分为“个人工作区”和“外部 Skill 来源”。个人工作区通过一个私有仓库双向同步独立的本地
  Skill、Prompt 和标签；外部来源仍然是只拉取的 Skill 仓库。
- 品牌 Logo 右侧提供统一同步按钮；未配置个人工作区时跳转到设置的 Git 同步页。
- 同步前展示上传、下载、删除与冲突计划；冲突可逐项选择保留本地状态或使用远程状态。
- 工作区完成后继续更新外部 Skill 来源，并刷新已托管的用户级和项目级部署。
- 移除来源只删除绑定和缓存 checkout，已导入 Library Skill 与不可变快照保留。

#### 2. Prompt 管理
- Prompt 列表、标签筛选和搜索
- 新建或导入 `PROMPT.md`
- 使用名称、描述、标签和正文四个字段创建或编辑，由服务端生成 `PROMPT.md`
- 新建和编辑时从与 Skill 共用的标签库中多选
- 服务端格式校验和 Hash 编辑冲突保护
- 一键将 Prompt 正文复制到设备剪贴板，并支持导出和删除
- 第一版不调用模型 API，也不复用 Skill Activation

#### 3. Projects（本机项目部署）
- 项目注册列表：路径、存在状态和项目级 Activation 数量
- 添加项目：路径必填，名称可选；省略名称时由后端使用项目根文件夹名称
- 选择项目后，从个人 Library 选择 Skill，按项目可用 Agent 勾选部署目标；重复项友好提示并自动跳过
- 按当前选中的 Agent 查看 Skill 详情，只展示该 Agent 对应的文档
- 选择软链接或复制模式，执行部署、解绑和注销
- Web UI 对重复部署和混用模式给出友好提示；底层 API 仍保留 `unchanged` 状态和冲突保护

本页面对应的项目注册信息保存到用户侧 `~/.skm/projects.yaml`。`copy` 完成后项目
目录中的 Skill 可以脱离 skm 运行；`link` 仍依赖用户侧 Library 快照。

## 目录结构

```text
skm/
├── cmd/skm/main.go          # 不变
├── internal/
│   ├── cli/
│   │   ├── app.go            # 增加 newUICommand()
│   │   ├── ui.go             # [NEW] skm ui 命令
│   │   └── ...
│   └── server/               # [NEW] HTTP API 服务
│       ├── server.go          # HTTP 路由和服务启动
│       ├── api_library.go     # Library 相关 API
│       ├── api_activation.go  # Activation 相关 API
│       ├── api_source.go      # Source 相关 API
│       └── api_overview.go    # Library 概览/Doctor/Version API
└── web/                      # [NEW] 前端静态资源
    ├── embed.go               # go:embed 指令
    ├── index.html
    ├── app.js
    ├── app.css
    ├── assets/                    # Claude/Codex 图标
    └── components/                # JS 组件模块
        ├── library.js
        ├── prompts.js
        └── projects.js
```

## REST API 设计

```text
GET    /api/dashboard          # Library 概览数据（Skill 与 Source 数量）
GET    /api/version            # 版本信息

GET    /api/skills             # 列出所有 Skill（?tag=xxx 筛选）
GET    /api/skills/:id         # Skill 详情
POST   /api/skills             # 添加 Skill {path, tags, source}
POST   /api/skills/detach      # 将项目跟随条目转为独立副本 {skill}
POST   /api/dialogs/skill-directory # 打开 macOS Finder 选择本地 Skill 目录
DELETE /api/skills/:id         # 移除 Skill

GET    /api/prompts            # Prompt 列表
POST   /api/prompts            # 创建 Prompt {name, description, tags, body}，也兼容 {content}
POST   /api/prompts/validate   # 校验结构化字段或未保存的 PROMPT.md
POST   /api/prompt-render      # 使用已保存 Prompt 或未保存内容渲染变量
GET    /api/prompts/:id        # Prompt 详情与原始内容
PUT    /api/prompts/:id        # 更新 Prompt {name, description, tags, body, baseHash}，也兼容 {content}
DELETE /api/prompts/:id        # 删除 Prompt

GET    /api/tags               # 所有标签及计数
POST   /api/tags               # 创建标签 {name}
DELETE /api/tags/:name         # 删除未使用且非默认的标签
PUT    /api/skill-tags         # 替换 Skill 标签 {skill, tags}
POST   /api/skill-tags/add     # 为 Skill 添加标签 {skill, tags}
POST   /api/skill-tags/remove  # 移除标签 {skill, tag}
POST   /api/tags/rename        # 重命名标签

GET    /api/status             # 当前 activation 状态
POST   /api/enable             # 启用 {skills, agents, mode}
POST   /api/disable            # 禁用 {skills, agents}
GET    /api/plan               # 查看 plan
POST   /api/apply              # 应用 plan

GET    /api/sources            # Source 列表
POST   /api/sources            # 添加并导入 Git Source {input, name?, ref, paths, tags}；继续兼容 url
POST   /api/sources/:name/update  # 更新 Source
DELETE /api/sources/:name      # 删除 Source 绑定和缓存 checkout，保留 Library 快照
POST   /api/sync               # 逐来源同步，并刷新托管部署；返回每个来源的结果

GET    /api/workspace          # 个人工作区配置和本机同步状态
PUT    /api/workspace          # 连接并校验个人工作区 Git 仓库
GET    /api/workspace/preview  # 三方比较 Skill 与 Prompt，返回同步计划
POST   /api/workspace/sync     # 带冲突选择执行同步并刷新托管部署

GET    /api/doctor             # 健康检查

GET    /api/projects           # 本机注册项目列表
POST   /api/projects           # 登记项目 {path, name}
GET    /api/projects/:id       # 项目详情、Activation 和部署状态
GET    /api/projects/:id/status # 项目部署状态
POST   /api/projects/:id/link # 软链接 {skill, agents, dryRun}
POST   /api/projects/:id/copy # 复制 {skill, agents, dryRun}
POST   /api/projects/:id/unlink # 解绑 {skill, agents, force}
DELETE /api/projects/:id      # 注销项目登记
```
