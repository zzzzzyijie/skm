# skm 发布指南

skm 通过 GitHub Release 提供预编译文件，并由同一个 Tag 通过 GitHub Contents API 自动更新
CLI 的 Homebrew Formula 与原生 App 的 Homebrew Cask。curl 安装器也从 GitHub Release 下载
CLI 文件并验证 SHA-256。

## 1. 一次性配置 Homebrew Tap

在 GitHub 创建公开仓库：

```text
zzzzzyijie/homebrew-tap
```

仓库默认分支必须是 `main`。创建一个只对该仓库拥有 Contents Read and Write 权限的
fine-grained Personal Access Token，并在 `zzzzzyijie/skm` 仓库中添加 Actions Secret：

```text
HOMEBREW_TAP_GITHUB_TOKEN
```

不能使用默认 `GITHUB_TOKEN` 更新另一个仓库；跨仓库发布需要单独 Token。发布工作流使用该
Token 调用 Contents API，而不依赖跨仓库 Git checkout 或 push。
将仓库改为公开只解决匿名下载，不会赋予 Actions 跨仓库写权限。fine-grained Token
必须满足以下配置：

- Resource owner 是 `zzzzzyijie`；
- Repository access 包含 `homebrew-tap`；
- Repository permissions 的 Contents 是 Read and write；
- `skm` 中的 Secret 名称严格为 `HOMEBREW_TAP_GITHUB_TOKEN`。

如果 Release 产物已成功，但工作流在 Homebrew 步骤失败，更新 Secret 后可在下一个 Tag
验证。也可以根据 Release 校验文件手动生成并提交 Formula 与 Cask：

```bash
sh scripts/generate_homebrew_formula.sh \
  v0.2.1 \
  ./checksums.txt \
  ../homebrew-tap/Formula/skm.rb

sh scripts/generate_homebrew_cask.sh \
  v0.5.2 \
  ./SKM-0.5.2-checksums.txt \
  ../homebrew-tap/Casks/skm-app.rb
```

## 2. 发布版本

发布前应先按 [隔离开发与发布流程](开发与发布流程.md) 完成开发二进制冒烟测试、
自动化验证和 GoReleaser Snapshot。确认 `main` 上的测试通过并且工作区干净，然后创建语义化版本 Tag：

```bash
git tag -a v0.2.0 -m "v0.2.0"
git push origin v0.2.0
```

`.github/workflows/release.yml` 将自动：

1. 在 macOS 26 runner 上运行 Swift 单元测试与隔离 XCUITest；
2. 构建 Universal 2 原生 App，签名、公证并生成 stapled ZIP/DMG；
3. 在干净的 Apple Silicon 与 Intel runner 分别检查签名、Gatekeeper、Core 握手和 App 启动；
4. 运行 Go 测试和安装器测试；
5. 构建 macOS/Linux 的 amd64、arm64 CLI 文件；
6. 生成校验文件和 GitHub Release，并上传原生 App 产物；
7. 根据 CLI 校验值生成并通过 Contents API 更新 `homebrew-tap` 仓库中的 `Formula/skm.rb`；
8. 根据原生 DMG 校验值生成 `Casks/skm-app.rb`，并在 App 产物上传后更新同一个 Tap。

Release 构建通过链接器把 Tag 版本注入 `skm version`。本地源码构建显示 `dev`；
通过 `go install ...@<version>` 安装时会从 Go 模块构建信息读取版本。

CLI 的 macOS tar.gz 仍由 SHA-256 与 Homebrew Formula 验证，并保留现有 `xattr` 兼容逻辑。
原生 `SKM.app` 使用独立的 Developer ID Application 签名、公证与 stapling 流程，不依赖该兼容逻辑。

### 2.1 一次性配置原生 App 发布凭据

先确认 Apple Developer Program 团队中存在有效的 **Developer ID Application** 证书，并在
持有私钥的 Mac 上从钥匙串导出为密码保护的 `.p12`。再在 App Store Connect 创建 Team API Key，
下载只会提供一次的 `.p8`，记录 Key ID 和 Issuer ID。

把二进制文件编码为单行 Base64：

```bash
/usr/bin/base64 -i DeveloperIDApplication.p12 | tr -d '\n'
/usr/bin/base64 -i AuthKey_KEYID.p8 | tr -d '\n'
```

在 `zzzzzyijie/skm` 仓库的 Actions Secrets 中配置：

```text
MACOS_DEVELOPER_ID_P12_BASE64       .p12 的 Base64
MACOS_DEVELOPER_ID_P12_PASSWORD     导出 .p12 时设置的密码
MACOS_NOTARY_PRIVATE_KEY_BASE64     .p8 的 Base64
MACOS_NOTARY_KEY_ID                 App Store Connect Key ID
MACOS_NOTARY_ISSUER_ID              App Store Connect Issuer ID
```

不要把 `.p12`、`.p8`、密码或 Base64 内容提交到仓库，也不要粘贴到 Issue、PR 或构建日志。
发布 job 会创建临时钥匙串，自动发现导入的 Developer ID Application 身份，完成后删除钥匙串。
本机真实签名、公证、stapling、Gatekeeper 验证和故障排查见
[macOS 原生 App 签名、公证与发布流程](Mac原生App签名公证与发布流程.md)。

## 3. 发布后验证

Homebrew：

```bash
brew update
brew install zzzzzyijie/tap/skm
skm version
```

curl：

```bash
curl -fsSL https://raw.githubusercontent.com/zzzzzyijie/skm/main/scripts/install.sh | sh
skm version
```

安装指定版本：

```bash
curl -fsSL https://raw.githubusercontent.com/zzzzzyijie/skm/main/scripts/install.sh | \
  sh -s -- --version v0.2.0
```

## 4. 本地检查发布配置

安装 GoReleaser 后执行：

```bash
goreleaser check
goreleaser release --snapshot --clean
```

Snapshot 不会创建 GitHub Release 或更新 Homebrew Tap。Formula 生成器可以单独测试：

```bash
sh scripts/generate_homebrew_formula_test.sh
sh scripts/generate_homebrew_cask_test.sh
```

安装器自身不依赖网络的测试：

```bash
sh scripts/install_test.sh
```

原生 App 的无凭据候选包：

```bash
sh macos/Scripts/package-release.sh \
  --version 0.5.2 \
  --build 2 \
  --output dist/macos \
  --preview
```

该命令检查 Swift App 与 Go Core 都是 Universal 2，并验证 App/Core/参数版本一致。它会使用
ad-hoc 签名并校验完整性，然后生成 ZIP、DMG 和独立校验文件；由于未使用 Developer ID 签名、
未公证，不能提供给最终用户。
